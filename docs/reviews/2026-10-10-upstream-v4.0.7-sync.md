# CC Switch 4.0.7 上游同步与 fork 功能兼容审查

把 `qwqwd65-ui/cc-switch` 的 3.x 底座同步到上游 **v4.0.7 正式稳定版**。同步在 `sync/upstream-v4.0.7-20261010` 候选分支进行，验证通过前不进入 main，也不发布 latest 更新清单。

Windows 单上一版回退开发暂停，保留在 `feat/windows-single-version-rollback`。此次同步没有包含它的未完成模块。

适配原则：上游已提供的功能直接沿用上游实现，删除重复的 fork 实现；只保留上游未覆盖的功能差异和必要的兼容修复。

## 上游大改

- 侧栏与按应用组织的页面取代旧布局；供应商卡片动作由模式状态统一计算。
- 新增直连、路由、聚合三种模式。故障转移队列仍使用供应商排序，但按钮与分区重写。
- Live 配置改为关键字段投影和事务写入，包含首次写入备份、冲突处理与崩溃恢复。旧整份覆盖及恢复函数需要重新适配。
- 用量统计成为独立全局页面，设置记录返回位置；会话、Skills、多应用管理重写。
- Codex 增加压缩会话读取与开关、Windows 运行检测与重启提示；修正额度缓存、定价及账号身份。
- 数据库 schema 升到 **20**。迁移后的数据库直接交给 3.x 会触发版本过新；安装旧二进制本身不能完成回退。

## 验证与发布

候选版本 `4.0.7-fork.1` 在 package.json、Cargo.toml、Cargo.lock、Tauri 配置中一致。保留 fork 的 Tauri CLI 2.11.5，并移植完整平台包与 integrity；其他依赖沿用上游。

`Upstream Sync Validation` 工作流只验证和上传候选产物：

1. frozen-lockfile 安装、TypeScript、格式、前端回归、renderer 构建。
2. Windows Rust 格式、Clippy、以独立进程运行的 nextest 回归。
3. 后端通过后构建 Windows NSIS 候选 Setup，作为 artifact 保存，不写入 releases/latest。
4. 失败摘要写公开工作流注解，完整日志作为 artifact 保存。

**本机只运行源码解析、格式化、git diff 检查，没有运行编译、完整类型检查、测试或安装包构建。** GA 结果记录在候选分支对应的运行中。

首次推送后，GitHub 曾以 Actions 使用规模为由暂停此 fork 的工作流，候选提交没有启动验证。2026-10-10 Ethan 已恢复工作流；补齐适配后重新推送触发候选验证，最终结果以该提交对应的 GA 运行记录为准。

恢复后首轮运行暴露了前端日志管道掩盖退出码的问题：默认 shell 下 `tee` 返回成功，但类型检查有 1 项错误、回归有 6 项失败。候选工作流已显式使用 Bash 的 pipefail，修正旧导航名称、代理新增参数的测试断言和测试 mock 配置类型；首轮绿色标记不作为通过依据。

首轮 Windows 编译 / Clippy 通过，后端 3,660 项回归中 4 项失败。原因是 fork 旧的 `base_instructions` 通用回填抢先写入模板指令，覆盖了上游新版从原生 `model_messages` 回填指令的路径，还把缺指令的无效目录错误地视为有效；已删除这项重复补丁，沿用上游实现。

签名安装、应用内更新、安装版 / 便携版识别及视频中的闪烁体验仍需用候选包在 Windows 上实际验收；CI 通过不替代设备交互检查。
